# Skill Preferences

Use this when the user asks an agent to create or update a skill.

## Defaults

- Use intuitive names that clearly describe the workflow.
- Keep frontmatter lean.
- Keep the skill as small as the workflow allows.
- Prefer concrete step sequences over broad guidance.

## Project Bias

- Prefer skills for repeatable project workflows such as phased implementation planning, browser verification, or asset-generation pipelines.
- Do not put durable project context into a skill if it belongs in `AGENTS.md`, `agent-reference/`, or `user-docs/`.
- If a skill depends on a project document, link to that document instead of duplicating its contents.
